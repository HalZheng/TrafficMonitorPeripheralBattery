# Settings

The plugin creates `PeripheralBatteryPlugin.ini` in the TrafficMonitor plugin
configuration directory on first load.

Two ways to edit it:

- **Options dialog** — the plugin manager's “选项” button opens a Win32 dialog
  listing only devices that are currently attached or have been configured
  before. It supports rescan, up/down ordering, and per-device
  show-on-taskbar/name/label/priority/colour. OK writes the INI back and
  applies the changes immediately.
- **Advanced settings** — the「高级设置...」button on the options dialog opens a
  second page with all global switches: offline retention, low-battery alerts
  and their threshold, grace window, `show_offline`, `stacked_show_percent`,
  `row_style`, `hybrid_rows`, `row_bar_width` and the four colour thresholds.
  Editing the four `color_*` values and per-device overrides is still INI-only.
- **Direct editing** — the INI stays a plain text file and can be edited by hand
  or generated by a script. The plugin checks the file timestamp about every
  two seconds and reloads it automatically.

Nothing here requires restarting TrafficMonitor. The host caches plugin item
pointers, so the plugin keeps exactly one permanent item and changes only what
it draws. Note that a manual edit is overwritten (comments and unknown keys
included) the next time the plugin saves the file.

## TrafficMonitor host settings

The plugin implements `ITMPlugin::OnExtenedInfo` and follows these host
settings, so it does not need its own duplicate toggles:

| Extended info | Host option | Effect in this plugin |
|---|---|---|
| `EI_TASKBAR_WND_NOT_SHOW_PERCENT` | 任务栏窗口“不显示百分号” | Removes `%` from the taskbar value and shrinks the item width. |
| `EI_MAIN_WND_NOT_SHOW_PERCENT` | 主窗口“不显示百分号” | Same, for the main-window item. |
| `EI_DRAW_TASKBAR_WND` | 任务栏窗口显示/隐藏 | Stops updating the taskbar item and drops host text colours when the taskbar window is off. |
| `EI_LABEL_TEXT_COLOR` | 标签文字颜色 | Used for the label when the host provides a colour. |
| `EI_VALUE_TEXT_COLOR` | 数值文字颜色 | Used for the percentage text when the host provides a colour. |

The plugin's own `color` field only controls the battery fill; it does not
override the host's text colours. There is no plugin-side “hide percent”
switch — the host setting is the single source of truth.

`display_mode=hybrid` and `display_mode=stacked` additionally depend on a host
layout option: turn off
**「水平排列」(horizontal_arrange)** in the taskbar window's display settings.
The host fixes the taskbar window height at `DPI(32)` and only hands an item
the full height when `IsDoubleLineExclusive()` is honoured, which happens in
the non-horizontal (or screen-edge taskbar) layout. With horizontal arrange
still on, the item only gets 21 px at 100% DPI and the plugin drops the row
labels; all values remain in the tooltip.

## Schema

```ini
[plugin]
refresh_interval_seconds=30
max_devices=6
priority_mode=fixed
show_offline=true
display_mode=stacked
presence_grace_seconds=300
keep_last_known=true
low_battery_notify=true
low_battery_notify_percent=10
single_item_notice_shown=true
color_auto_migrated=true
hybrid_rows=4
row_bar_width=48
row_style=solid
stacked_show_percent=false
battery_low_percent=20
battery_good_percent=60
cpu_orange_percent=50
cpu_red_percent=80
color_high=#4CAF50
color_medium=#FF9800
color_low=#F44336
color_charging=#03A9F4

[device:g03_pro]
hidden=false
name=AUSDOM G03 Pro
label=G03
priority=10
color=auto
```

Only devices that have been discovered or explicitly configured get a
`[device:...]` section; the compiled-in registry is never dumped into the INI.

## Fields

| Field | Values | Meaning |
|---|---|---|
| `refresh_interval_seconds` | 5–3600 | Polling interval. |
| `max_devices` | 1–8, default 6 | Maximum number of battery groups drawn inside the single taskbar item. |
| `priority_mode` | `fixed` | `fixed` sorts by per-device `priority`. `lowest` and `charging` are reserved. |
| `show_offline` | `true`/`false` | Show `--` when a device is offline; `false` shows an empty value. |
| `display_mode` | `bar` / `text` / `hybrid` / `stacked` | `bar` draws one battery group per device horizontally; `text` concatenates them as host-rendered text; `hybrid` draws four stacked rows (CPU, memory, up to two batteries); `stacked` draws three — CPU, memory, then two separate battery icons side by side — and is the recommended legible option. Unknown values fall back to `bar`. |
| `presence_grace_seconds` | 0–3600 | How long a device that **never reported a level** stays visible (showing `--`) after its receiver disappears. `0` removes it immediately. Devices with a cached reading are unaffected — see below. |
| `keep_last_known` | `true`/`false`, default `true` | Keep showing the last measured level, with a small offline badge, after a device sleeps or stops answering. `false` restores the old behaviour: `--` during the grace window, then the item disappears. The cache is memory-only and is cleared on host restart. |
| `low_battery_notify` | `true`/`false`, default `true` | Show one taskbar notification when a live reading drops to the alert threshold. Cached (stale) readings and charging devices are excluded, and each device needs to recover by 5 points before it can alert again. |
| `low_battery_notify_percent` | 1–100, default 10 | Alert threshold, independent of `battery_low_percent` (which only controls colour). |
| `single_item_notice_shown` | `true`/`false` | Whether the one-time upgrade hint was already displayed. |
| `color_auto_migrated` | `true`/`false` | One-time migration of the old rotating default palette to `auto`. Set automatically; do not edit. |
| `hybrid_rows` | 2–4, default 4 | Total rows. The first two are always CPU and memory; the rest are batteries in priority order (max 2). Fewer devices means fewer, taller rows. |
| `row_bar_width` | 16–160, default 48 | Width of each row's progress bar at 96 DPI. |
| `row_style` | `solid` / `framed`, default `solid` | `solid` removes the outline, inset and vertical padding so the coloured fill occupies the whole row (about 7 px instead of 2 px) and uses a 1 px gap between label and bar. `framed` keeps the old 1 px stroke + 2 px inset as a rollback option. Unknown values fall back to `solid`. |
| `stacked_show_percent` | `true`/`false`, default `false` | In `stacked` mode, hides all percentages so the grid is as narrow as possible. `true` adds a measured value column to every cell and to the system rows; the whole grid widens and stays aligned. |
| `battery_low_percent` | 1–98, default 20 | Battery at or below this is red. |
| `battery_good_percent` | `battery_low_percent`+1 – 100, default 60 | Battery at or above this is green; between the two thresholds is orange. |
| `cpu_orange_percent` / `cpu_red_percent` | defaults 50 / 80 | CPU and memory usage thresholds for orange / red; below the orange threshold is green. |
| `color_high` / `color_medium` / `color_low` / `color_charging` | `#RRGGBB` | Green / orange / red / charging colours. Dark mode lifts each colour towards white automatically. |
| `device:<id>.hidden` | `true`/`false` | Keep the device configured but keep it off the taskbar. Old `enabled=false` is migrated to `hidden=true` on load. |
| `device:<id>.name` | string | Display name, also used in the tooltip. |
| `device:<id>.label` | string | Short taskbar label. In `hybrid` mode it is drawn in a 7 px font inside a 26 px label column. |
| `device:<id>.priority` | integer | Lower values sort first in `fixed` mode. In `hybrid` mode only the first one or two devices are drawn; the dialog's up/down buttons rewrite these. |
| `device:<id>.color` | `auto` / `#RRGGBB` | `auto` (default) colours the fill by charge level; an explicit hex colour overrides it. Offline is always grey and charging keeps its own colour. |

## Display modes and level colours

`bar` and `hybrid` share one colour rule, following the common mobile battery
convention rather than a per-device palette:

| State | Colour |
|---|---|
| Battery ≥ `battery_good_percent` | green (`color_high`) |
| Battery between the two thresholds | orange (`color_medium`) |
| Battery ≤ `battery_low_percent` | red (`color_low`) |
| Charging (any level) | cyan blue (`color_charging`), value keeps its `+` suffix |
| Never reported / unknown level | grey, value `--` |
| Sleeping, cached last-known level | unchanged level / charging colour, plus an offline badge |
| CPU / memory ≥ `cpu_red_percent` | red |
| CPU / memory ≥ `cpu_orange_percent` | orange |
| CPU / memory otherwise | green |

The neutral greys used for the battery track, the offline outline and the
offline badge are tinted 20 % towards `EI_VALUE_TEXT_COLOR` when the host uses
a custom text colour. With no colour, or the built-in black / white defaults,
they are left exactly as-is: the standard appearance is unchanged.

CPU and memory values come from `ITMPlugin::OnMonitorInfo`, which the host calls
once per monitor cycle (default 1000 ms) immediately after `DataRequired()`.
No PDH counters, `GlobalMemoryStatusEx` or extra thread are involved. The
official status bar hooks (`IsDrawResourceUsageGraph` /
`GetResourceUsageGraphValue`) are deliberately not used: one item can only
report a single value and they depend on the host's `show_status_bar` option,
so they cannot produce four independent rows.

In `hybrid` mode `GetItemWidthEx()` returns the widest single row instead of
the sum of all device groups, which is what actually reduces the taskbar
footprint. With the full 32 px height (non-horizontal layout), four rows are
about 8 px each and use 7 px labels; when only 21 px is available the plugin
drops the labels, draws four plain bars and keeps every value in the tooltip.

### `stacked`: three rows, readable text

`stacked` trades the fourth row for legibility. A 32 px slot splits into
10 / 10 / 12 px (the last row takes the integer remainder), so the row font
grows from 7 px to 9 px and the third row can hold two complete 16x10 battery
icons with their labels.

All three rows share **one grid**: a measured label column, a 4 px gap, then
content. The CPU/memory bar and the first battery icon start at exactly the
same x; the last battery icon (or its value) ends at exactly the right edge.
`GetItemWidthEx()` returns `cells * cellWidth + (cells - 1) * cellGap`, so no
column is ever stretched and no blank space is left after either group. At
100% DPI the default (percentages hidden, two devices) is about **98 px** —
narrower than `hybrid`'s ~100 px and roughly half of the old ~194 px
three-device horizontal row. Setting `stacked_show_percent=true` adds a
measured value column to every cell, widening the grid to about 152 px while
keeping every edge aligned.

With one device the grid shrinks to a single cell (no empty second column);
with no devices only the two system rows are drawn. Below 28 px the renderer
falls back to plain bars and battery silhouettes without labels.

Removing margins, insets and outlines does **not** increase a row's height
budget: `h` is `rect.Height()` supplied by the host. What it does is return the
pixels previously spent on a 1 px stroke, a 2 px inset and vertical centring
to the coloured fill — from roughly 2 px to roughly 7 px, which is a 3.5×
visual gain and matches the host's own `TryDrawStatusBar` (a plain fill with an
optional dashed outline, off by default). Only two things actually make a row
taller: fewer rows (`hybrid_rows=3` gives ~10.7 px) or a higher system DPI
(the host scales `DPI(32)`).

## Plugin commands

The host's plugin menu offers three commands:

| Command | Effect |
|---|---|
| 立即刷新 | Re-poll every device immediately, clearing the failure backoff. |
| 打开设置文件 | Open `PeripheralBatteryPlugin.ini`; edits are reloaded within about two seconds. |
| 诊断信息 | Show a Ctrl+C-copyable report: the version of the DLL the host actually loaded, module and INI paths, effective settings, and each discovered device's online / cached / last-reading / consecutive-failure state. Start here when a new option is missing or a device stays at `--`. |

## Sleeping / offline devices

When a keyboard or mouse sleeps, its receiver usually stays enumerated but
stops answering battery requests (or disappears entirely). The plugin keeps the
last successful `BatteryReading` per device in memory and reuses it:

- The percentage, fill length and level/charging colour are **unchanged**. The
  only visual difference is a small high-contrast `x` badge in the top-right
  corner of the battery icon (`bar`, `stacked`) or the row bar (`hybrid`, and
  `stacked` when the slot is shorter than 28 px). `text` mode keeps the plain
  value — the host fixes that column's width from `GetItemValueSampleText()`,
  so appending a marker there would clip the number.
- The tooltip adds「离线，最后读数 · N 分钟前」so a cached value is never
  mistaken for a live measurement (and is the only offline hint in `text` mode).
- The device stays visible until it answers again, so the number of rows/cells
  and the item width no longer change when something falls asleep. Restarting
  TrafficMonitor clears the cache; a hidden device is never drawn.
- A device that has never produced a valid reading still shows `--` for
  `presence_grace_seconds` and then disappears.
- Reads are retried every polling interval for a device that has worked before,
  so waking it clears the badge promptly. Devices that never worked keep the
  exponential backoff to avoid hammering an unsupported interface.

Set `keep_last_known=false` to return to the old behaviour.

## Item ID

TrafficMonitor sees exactly one plugin item with ID `peripheral_battery` and
name「无线外设电量」. That ID is the key in the host's `plugin_display_item`
list and must stay stable. Device IDs are internal to the plugin and are only
used as INI section names.

## Adding settings for a new device

`device:<id>` must match the `DeviceDescriptor::id` in
`src/core/DeviceRegistry.cpp`. A section is created lazily, the first time the
device is detected or the user edits it, so adding a descriptor does not bloat
existing configuration files.
